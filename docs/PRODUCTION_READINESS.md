# JoySafeter 上线前门禁

本文只定义正式发布前必须验证的条件，不记录某次开发过程、测试数量或已完成事项。每次候选发布
应在 Issue、发布单或值班系统中记录负责人、验证日期和证据链接。

## 发布原则

- 任一关键门禁没有可复现证据时，不得正式发布。
- 镜像、配置、数据库迁移和回滚方案必须对应同一 Git SHA。
- 本地 Compose 验证通过不等于生产环境验证通过。
- 未实现的部署能力不通过文档或手工步骤声明为“已支持”。

## 1. 构建与供应链

- [ ] backend、frontend、orchestrator-rs、SkillSpector 和 Agent runtime 使用不可变版本 tag。
- [ ] 每个镜像可追溯到 Git SHA、依赖锁文件和构建流水线。
- [ ] `amd64`、`arm64` 镜像分别完成构建，并验证合并后的 manifest。
- [ ] 镜像完成漏洞扫描、SBOM、provenance、签名和部署侧身份校验。
- [ ] 在目标架构执行镜像拉取、数据库迁移、服务启动和 Agent 任务冒烟测试。

## 2. 发布与回滚

- [ ] 发布命令、回滚命令和紧急停机步骤写入当次发布 Runbook。
- [ ] 数据库迁移已在生产规模副本数据上验证耗时、锁影响和失败恢复。
- [ ] 已验证应用版本回滚，并明确数据库迁移是否允许回退。
- [ ] 配置变更、密钥变更和镜像变更可独立定位与恢复。

## 3. 数据安全

- [ ] PostgreSQL、Redis、对象存储和日志使用独立持久化方案。
- [ ] 自动备份已启用，并从真实备份完成恢复演练。
- [ ] 数据保留、导出、删除和审计策略已确定。
- [ ] Redis 丢失、重启和故障转移时的系统行为已验证。

## 4. 密钥与网络

- [ ] `JOYSAFETER_VAULT_ENCRYPTION_KEY`、数据库密码、模型密钥和第三方凭据不进入 Git、日志或镜像层。
- [ ] Vault 加密密钥在所有副本间一致并纳入备份；发布或重启不会重新生成。
- [ ] 所有默认密码和示例凭据已替换。
- [ ] Frontend 与 API 仅通过 HTTPS 暴露。
- [ ] PostgreSQL、Redis、Docker socket 和 orchestrator gRPC 不暴露公网。
- [ ] Sandbox 出站策略按最小权限验证，凭据只发送到目标域名。

## 5. 可靠性

- [ ] API、worker、orchestrator-rs、SkillSpector、PostgreSQL 和 Redis 的重启恢复已验证。
- [ ] 任务超时、取消、重试、重复请求和进程中断场景已验证。
- [ ] 单实例故障不会留下无法识别的永久运行任务或孤儿 Sandbox。
- [ ] 数据库、Redis、模型提供方和 SkillSpector 不可用时，系统行为符合预期。
- [ ] 容量上限、并发限制、队列积压和降级策略已确定。

## 6. 可观测性

- [ ] 关键服务具备健康检查、结构化日志、指标和告警。
- [ ] 能按组织、项目、会话、任务和 Sandbox 关联完整请求链路。
- [ ] 告警覆盖错误率、延迟、任务积压、重试、死信、数据库连接和磁盘容量。
- [ ] 日志已脱敏，不记录密钥、Authorization header 或完整用户凭据。
- [ ] 值班人员可以仅凭 Runbook 定位并恢复常见故障。

## 7. 性能与容量

- [ ] 使用接近生产的数据量完成 API、任务执行和事件流压测。
- [ ] 明确单实例安全容量和水平扩容触发条件。
- [ ] SkillSpector 与 Agent runtime 的 CPU、内存、磁盘限制已验证。
- [ ] 长任务、大事件流和高并发下不存在无界内存或磁盘增长。
