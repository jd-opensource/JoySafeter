# 教程 06：用环境控制沙箱的网络与运行时

> **适合人群**：需要让智能体**安全地访问外网或第三方服务**、或给沙箱挂数据卷 / 注入非敏感变量的用户。
> **前置**：已能构建并运行一个智能体（见 [教程 04](./04-agent-build-and-run.md) 或 [新手手册](./00-getting-started.md)）。

**环境（Environment）** 是智能体的“运行环境模板”，在 **托管智能体 → 环境**（`/managed/environments`）管理。它决定一个会话的沙箱：

- **能不能上网、能访问哪些主机**（网络策略）；
- **能连哪些需要鉴权的第三方服务**（出站鉴权，凭据不进沙箱）；
- 挂哪些**数据卷**、注入哪些**非敏感环境变量**。

> 为什么需要它：每个会话的沙箱**默认全禁外网出口**（这是平台的安全底线）。要让智能体访问互联网或内部服务，就得用环境**显式放行**。

---

## 1. 新建环境

进入 **托管智能体 → 环境**，点 **新建环境**，填**基础配置**：

- **名称**：例如 `python-dev`、`recon-restricted`。
- **描述**（可选）。
- **网络配置**：两选一——
  - **限制访问（推荐）**：默认禁外网，只放行你列出的主机和已配置的第三方服务。
  - **不限制**：允许沙箱访问任意外网。**仅建议在可信环境或调试时使用。**

选“限制访问”后，在 **允许的主机** 里填沙箱可直连的外网主机（逗号或换行分隔），例如：

```
api.example.com
github.com
*.internal.example.com
```

> 已配置的第三方服务地址会**自动放行**，不用在这里重复填。

---

## 2. 第三方服务出站鉴权（核心能力）

如果技能要访问一个**需要 token 或 cookie 的第三方 HTTP 服务**，又不想让真实凭据进沙箱，就用这里。**机制**：技能用 `http://` 访问一个地址，平台在**网关**用你选的服务凭据完成认证，再**回源到真实的 https 地址**——**真实 token / cookie 永远不进沙箱**、不写日志、不进事件流。

### 步骤

1. **先建服务凭据**：到 **模型与凭据**（`/managed/secrets`）点 **新建连接或凭据**，类型选 **服务凭据**，把 token 或完整 cookie 存成一个凭据字段（例如 `API_TOKEN`、或 `COOKIE_HEADER=thor=...; pin=...`）。
   > 环境编辑器里也有“**去创建服务凭据…**”的快捷入口。
2. 回到环境，在 **第三方服务** 区 **添加服务**，填：
   - **真实地址**：第三方接口的真实地址，**含 `https://`**（如 `https://api.example.com`）。
   - **服务凭据**：选第 1 步建的那条。
   - **认证方式** + **凭据字段**：告诉平台用凭据里的哪个字段、以什么形式注入认证——
     - **Bearer / 自定义 Header**：选**凭据字段**（区分大小写），平台读取其值注入 `Authorization` 或指定 Header。
     - **Cookie**：选保存**完整 Cookie header 字符串**的凭据字段（如 `COOKIE_HEADER`），平台注入 `Cookie: <该字段值>`。
   - **允许的接口路径**（强烈建议填）：一行一个路径。以 `/` 结尾是**前缀匹配**（该目录下全部），否则是**精确匹配**（仅该接口）。**留空 = 放行该地址下所有接口**；高权限凭据建议逐条列出以防越权。例如：

     ```
     /api/warning/getWarningDetailById
     /api/warning/work/
     ```
3. 看 **预览** 里的 **Skill 使用** 示例地址——**在技能里就用这个 `http://` 地址访问**，认证由平台自动加上。

---

## 3. 环境变量与数据卷（可选）

在环境的**高级选项**里还能配：

- **环境变量**：注入沙箱的**非敏感**变量，格式 `KEY=value`（逗号或换行分隔）。
  > ⚠️ **不要**在这里放 token / cookie / API key 等敏感值——那些请一律存**服务凭据**（见 §2）。
- **数据卷挂载**：把持久化存储挂进沙箱工作目录。
- **安装包**：环境预装的依赖。

---

## 4. 在哪里用上这个环境

环境建好后，在这些地方选用它：

- **创建会话时**：高级选项里选 **运行环境**（连同 MCP 凭据库、文件、Memory、Git 一起）。
- **触发器**：把“运行环境”从“跟随 Agent 默认”改成指定环境（见 [教程 05](./05-triggers.md)）。
- **快速开始向导**：引导流程中的“配置环境”步骤。

> 改了环境后，**新开的会话**才会用到新配置；已在运行的会话用的是它启动时的设定。

---

## 5. 安全建议（必读）

- **默认选“限制访问”**，按需逐个加允许主机，别图省事用“不限制”。
- **敏感值只进服务凭据**，永不放环境变量；真实凭据不进沙箱是这套设计的核心保证。
- **给第三方服务列“允许的接口路径”**，把高权限凭据能触达的接口收窄到最小集合，防止技能越权调用。
- **给自动运行（触发器）配网络受限的环境**，避免无人值守时越权外联。

---

## 常见问题

**Q：技能连不上我的第三方服务？**
A：确认三点——① 会话创建时选了这个**运行环境**；② 第三方服务的**真实地址**填了含 `https` 的正确地址，且技能里用的是预览给出的 `http://` 地址；③ 目标接口在**允许的接口路径**范围内（留空则全放行）。

**Q：为什么技能里要用 `http` 而不是 `https`？**
A：技能对沙箱内网关发的是 `http`，网关替你完成认证并回源到真实的 `https`。这样真实 token / cookie 不必进沙箱。

**Q：直连外网主机（不需要鉴权）怎么放行？**
A：不用配第三方服务，直接把主机名加到**允许的主机**白名单即可。

**Q：环境变量里能放 API Key 吗？**
A：不能。环境变量只放非敏感值；凭据请建**服务凭据**，并在第三方服务里引用。
