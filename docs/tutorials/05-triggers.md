# 教程 05：用触发器让智能体自动运行

> **适合人群**：想让智能体**不用手动开会话**就能定时或被外部事件触发的用户。
> **前置**：已有一个能正常运行的智能体（见 [教程 04](./04-agent-build-and-run.md) 或 [新手手册](./00-getting-started.md)）。

触发器（Trigger）让智能体**自动运行**，统一在 **自动化 → 触发器**（`/managed/triggers`）管理。三种类型：

| 类型 | 什么时候用 |
|---|---|
| **计划（Cron）** | 按周期（如每天 09:00）或在某个设定时间**触发一次** |
| **Webhook** | 外部系统发来一个**签名的 HTTP 请求**时触发 |
| **手动** | 保存一个按需触发器，只通过“立即运行”执行 |

---

## 1. 打开触发器页面

进入 **自动化 → 触发器**（`/managed/triggers`），点 **新建触发器**，选择类型。列表可按类型和状态（已启用 / 已禁用 / 已完成 / 自动禁用）筛选。

所有类型都要填这几项**公共字段**：

| 字段 | 说明 |
|---|---|
| **名称** | 例如“每日报告” |
| **智能体** | 触发时运行哪个智能体 |
| **触发后执行内容** | 给智能体的提示词；Webhook 场景可用 payload 变量（如 `{{ body.chat_id }}`） |
| **运行环境** | 保持“跟随 Agent 默认”即用该智能体自身的环境；也可指定一个独立[环境](./00-getting-started.md) |
| **超时（秒） / 最大重试次数** | 单次运行的时限与失败重试 |
| **启用** | 关掉后不会被调度或 Webhook 触发 |

---

## 2. 创建「计划（Cron）」触发器

1. 类型选 **计划**。
2. 填公共字段（智能体、触发后执行内容等）。
3. **设置调度**——“何时”有两种：
   - **重复**：用 **预设**（每 5 分钟 / 每小时 / 每天 09:00 / 工作日 09:00 / 每周一 / 每月 1 日…）、**构建器**（选频率、小时、分钟、星期），或 **高级** 直接写标准 5 字段 cron 表达式（`分 时 日 月 星期`）。别忘了选 **时区**；页面会预览“接下来的运行”。
   - **仅一次**：选一个**未来时间**，只触发一次，之后保持空闲。
4. **并发策略**（仅治理定时触发之间的重叠；手动“立即运行”总会执行）：
   - **允许重叠** / **运行中则跳过** / **替换正在运行的**。
5. 保存。

---

## 3. 创建「Webhook」触发器

Webhook 让外部系统用一个 HTTP 请求启动会话。为安全起见**务必开启签名校验**。

1. 类型选 **Webhook**，填公共字段。
2. **认证方式**（至少接受一种，**推荐 HMAC 签名**）：
   - **HMAC 签名** / **Bearer 令牌** / **Token 头**。
3. **配置签名密钥**：把密钥存成一条**服务凭据**（在[模型与凭据](./00-getting-started.md)里创建，类型选“服务凭据”），然后在触发器里选中该**服务凭据**及其**凭据字段**。
   > 真实密钥存在服务凭据里，**不会写进触发器明文**。
4. **投递过滤（可选）**：加条件（如路径 `body.data.direction` = 值 `inbound`）。不满足条件的请求会被**接受（HTTP 200）并记录，但不启动运行**。
5. **去重头（可选）**：在指定的请求头上携带相同值的重复投递会被忽略。
6. **会话模式**：决定每次触发落到哪个会话（见 §4）。
7. 保存后，用 **复制 URL** 拿到端点地址，用**签名请求示例（cURL）**拿到一段带正确签名的可运行请求；上线前用 **测试触发** 验证（禁用状态也能测）。

> 端点有限流（约 60 次/分钟）。外部系统 POST 到该端点，并按所选认证方式签名即可触发。

---

## 4. 会话模式怎么选（Webhook / 计划）

| 模式 | 行为 | 适合 |
|---|---|---|
| **每次新会话（fresh）** | 每次触发都开一个全新会话 | 相互独立的一次性任务 |
| **复用会话（reuse）** | 首次触发建会话，之后空闲时复用同一个 | 想让上下文累积的周期任务 |
| **固定会话（pinned）** | 始终投递到你选定的某个会话（须空闲） | 定向注入到一个长期会话 |
| **按键分会话（keyed）** | 按渲染出的**会话键**分别路由（每个键一个会话） | 按用户 / 会话 ID 隔离，如 `{{ body.chat_id }}` |

---

## 5. 运行、测试与查看历史

- **立即运行**：手动触发一次（用幂等键去重），任何类型都可用。
- **测试触发**：Owner 验证用，禁用状态也能跑。
- **查看运行记录 / 运行历史**：看每次的触发时间、开始 / 完成时间、重试次数、错误，以及**打开对应会话**。

---

## 6. 自动禁用与恢复（dead-letter）

触发器**连续失败**达到阈值会被**自动禁用**，避免无效地反复触发。在其详情页会看到“此触发器已被自动禁用”和失败原因；**重新启用**即可清除该状态、恢复触发并重算下次运行时间。

> 另外，项目层面可以整体**暂停触发**；暂停期间该项目的定时触发不会执行。

---

## 7. 安全建议（必读）

- **Webhook 一律签名**：优先 HMAC，密钥存**服务凭据**，绝不写进明文配置。
- **用投递过滤和去重头**：只让符合条件的请求真正启动运行，抵御误触和重放。
- **最小化提示词里的信任**：payload 变量来自外部，别在提示词里让智能体无条件执行 payload 内容。
- **收敛运行环境**：给触发器指定网络受限的[环境](./00-getting-started.md)，避免自动运行时越权访问外网。

---

## 常见问题

**Q：触发了但没启动运行？**
A：多半是**投递过滤**没匹配（会记录但不运行）、命中**去重头**、或**并发策略**为“运行中则跳过”。看运行历史里的原因。

**Q：Webhook 返回 200 却没跑？**
A：这是设计行为——不满足投递过滤的请求会被接受并记录，但不启动运行，避免给外部系统报错。

**Q：签名怎么配才对？**
A：用 `GET .../webhook-sample`（界面上的“签名请求示例”）拿到带正确签名的 cURL，照着设置 BODY 和密钥即可；密钥就是你在触发器里选的那条**服务凭据的凭据字段**的值。

**Q：触发器被自动禁用了怎么办？**
A：进详情页看失败原因，修好后**重新启用**即可恢复。
