# JoySafeter 使用手册（新手上手）

> **适合人群**：第一次接触 JoySafeter 的终端用户 / 安全工程师。
> **读完你能做到**：登录平台 → 配好一个模型接入 → 用一个安全智能体（Agent）跑起来 → 看它实时干活 → 拿到结果。
> **不需要**：懂代码、懂后端、懂 API。全程在网页界面操作。

如果你想深入某一块，本手册每一步都会指向对应的进阶教程（01–04）。

---

## 1. JoySafeter 是什么，能帮我做什么

JoySafeter 是一个**自托管的「智能体（Agent）运行平台」，专为安全工作打造**。

你只需要用一句话描述你想要的智能体（比如“帮我对这个授权网站做渗透测试并出报告”），
再选好它用哪个大模型、能用哪些工具和技能，平台就会把这个智能体**放进一个隔离的沙箱**里替你自动执行，
你在网页上就能实时看到它的每一步思考、每一次工具调用，最后拿到它产出的报告。

一句话：**你定义智能体，平台在你自己的服务器上安全地替你把它跑起来。**

它和普通“云端 AI 助手”的关键区别：

- **数据不出你的网络**：提示词、目标信息、扫描结果全部留在你自己的基础设施里。
- **执行被牢牢隔离**：每个会话都在独立的加固沙箱里运行，默认**禁止一切外网出口**，除非你在“环境”里明确放行。
- **工具和技能可控**：技能会被安全扫描，未通过扫描 / 未审批的技能不会被装进沙箱。
- **凭据不进沙箱**：访问第三方服务用到的 token / cookie 由平台在网关注入，**真实凭据永远不暴露给沙箱**。

### 典型能做的事

- **APK 漏洞检测**：上传一个 APK，智能体自动做静态 + 动态分析，输出一份 OWASP Mobile Top 10 报告。
- **渗透测试**：给一个**已授权**的目标 URL 和测试范围，智能体自行规划、执行、按发现调整策略，最后交报告。
- 以及任何你能用“引擎 + 模型接入 + 技能 + 工具”组合出来的安全自动化流程。

> ⚠️ **务必只对你有合法授权的目标使用。** 平台是能力工具，合规责任在使用者。

## 2. 打开平台并登录

### 2.1 前置：平台得先装好

本手册假设平台已经由你或你的团队部署好了（部署是一次性的运维动作，见
[安装入口](../../INSTALL_CN.md)）。部署完成后，浏览器访问：

| 你要用的 | 地址 |
|---|---|
| **产品界面（你几乎只用这个）** | `http://localhost:3000` |
| API（一般用不到） | `http://localhost:8000` |

> 如果部署在远程服务器上，把 `localhost` 换成服务器地址即可。

### 2.2 注册 / 登录

打开 `http://localhost:3000`，你会看到登录页：

- **首次使用**：点“注册”，用邮箱创建账号（部分部署需要邮箱验证）。
- **已有账号**：直接用邮箱密码登录。
- **企业 SSO**：如果管理员开了单点登录，你还能用 GitHub / Google / Microsoft / OIDC / 京东 SSO 直接登录。

登录后右下角头像菜单里可以随时**切换中文 / English、切换深浅色主题、退出登录**。

### 2.3 认识“组织 / 项目”与权限

登录后，界面左上角有一个**组织 / 项目切换器**。JoySafeter 用它来隔离不同团队和工作空间，层级是：

```
组织 Organization（团队边界）
 └─ 项目 Project（资源作用域）
      └─ 智能体 / 会话 / 模型接入 / 服务凭据 / MCP 凭据库 / 环境 / 技能 / 触发器 …
```

- **组织（Organization）**：你所在的团队，划定“谁在一个团队里”。
- **项目（Project）**：组织下的一个工作空间，划定“资源归谁、谁能动”。**你建的每一样东西都属于某个项目**——切换项目，你看到的智能体、会话、凭据会整套切换。

**权限分两层，各管一件事：**

| 层 | 角色 | 决定 |
|---|---|---|
| 组织角色 | `owner` / `admin` / `member` | 你是不是“组织超级用户” |
| 项目角色 | `admin` / `editor` / `viewer` | 你在**这个项目**里能干什么 |

实际能干什么，按这个规则算：

- **组织 owner / admin** → 在**所有项目**里都是管理员，无需单独授权；owner 还能管理组织本身。
- **普通 member** → 能力**完全由你在该项目的角色决定**，没被加进项目就**无权访问**：
  `viewer` 只读、`editor` 可写（建改删；查看凭据明文也需要写权限）、`admin` 可管理该项目。

> 组织角色和项目角色**不做交集**——普通成员进项目要单独授权，新成员默认是最小权限 `viewer`。
> 团队与权限在左侧 **管理**（组织 / 项目 / 成员）里维护。

新账号通常会有一个默认组织和项目，**你直接用默认的就行**，需要时再切换或新建。

## 3. 界面速览（左侧导航）

登录后，所有功能都在**左侧导航栏**，分成几个分组。你日常最常用的只有加粗的几项：

| 分组 | 菜单项 | 作用 |
|---|---|---|
| **托管智能体** | **快速开始** | 用一句话描述需求，向导式地建出并跑起一个智能体（新手首选） |
| | **智能体** | 手动创建 / 编辑你的智能体（Agent） |
| | **会话** | 你和智能体的每一次对话都在这里，实时看它干活 |
| | 环境 | 智能体的“运行环境模板”：网络策略、允许主机、第三方服务、数据卷、环境变量 |
| | MCP 凭据库 | 存放外部工具（MCP 服务器）的加密访问凭据 |
| **自动化** | 触发器 | 让智能体按定时 / Webhook 自动运行 |
| **智能体资源** | **模型与凭据** | 配置**模型接入**（大模型 + 访问密钥）和**服务凭据**，**几乎是你的第一步** |
| | 技能 | 导入、扫描、审批“技能包”，给智能体加执行能力 |
| | 文件 | 上传给智能体使用的文件（如待检测的 APK） |
| | 数据卷 / 记忆 | 持久化存储与智能体的长期记忆 |
| **分析监控** | 概览 / 调用历史 | 用量、成本、调用记录 |
| **管理** | 组织 / 项目 / 成员 / 项目访问令牌 | 团队与权限管理；**项目访问令牌**供外部程序调用本项目 API |

> 你只要跟着下面的主线走，用到哪个菜单我会明确告诉你。

## 4. 先建立几个核心概念（2 分钟）

在动手前，理解这几个词能让后面顺很多。JoySafeter 把“凭据类”的东西分得很清楚，**各有各的用途，别混淆**：

### 4.1 三类“凭据类”对象——都在哪、干什么

| 对象 | 在哪配置 | 用途 |
|---|---|---|
| **模型接入（Model Connection）** | 智能体资源 → **模型与凭据** | 告诉平台“用哪个大模型 + 哪把访问密钥”，供智能体调用 LLM |
| **服务凭据（Service Credential）** | 智能体资源 → **模型与凭据** | 存放访问**第三方 HTTP 服务**的 token / cookie，用于**环境的出站鉴权**或**触发器的入站鉴权** |
| **MCP 凭据（在 MCP 凭据库内）** | 托管智能体 → **MCP 凭据库** | 存放 **MCP 服务器**的 Bearer 凭据，让智能体能调用外部 MCP 工具 |

> 还有一个**项目访问令牌**（管理 → 项目访问令牌），那是给**外部程序**反过来调用 JoySafeter API 用的，和上面三类方向相反，普通使用一般用不到。

### 4.2 其余关键概念

- **引擎（Engine）**：真正“开动”智能体的运行时。可选 `claude` / `codex` / `native` / `pi`。新手直接选 **`claude`** 最省心。
- **智能体（Agent）**：一份定义 = 引擎 + 模型接入 + 系统提示词（它的角色和规矩）+ 技能 + 工具 + MCP。
- **会话（Session）**：你和某个智能体的一段对话。你发一条消息，它就执行一次任务，你在会话里实时看结果。创建会话时可以选**运行环境**和 **MCP 凭据库**。
- **环境（Environment）**：智能体的运行环境模板——决定沙箱**能不能上网、能访问哪些主机、能连哪些第三方服务**，以及数据卷挂载和非敏感环境变量。
- **技能（Skill）**：一个能被智能体读取 / 执行的“能力包”（一堆脚本 + 说明），比如“移动端渗透测试”。需经安全扫描并审批后才可用。
- **沙箱（Sandbox）**：每个会话独享的隔离容器，智能体的所有动作都关在里面，默认断网、非 root。

它们的关系可以记成一句话：

> 先在**模型与凭据**里配好一个**模型接入** → 用它 + 一个**引擎** + 一些**技能/工具/MCP** 组装出一个**智能体** →
> 开一个**会话**（按需选**环境**和 **MCP 凭据库**）让它在**沙箱**里跑。

## 5. 主线：从零到跑起第一个智能体

下面有**两条路**，达成的效果一样。**新手强烈建议走 A（快速开始向导）**，它把所有步骤串成一个引导流程。
如果你想完全掌控每一步、或以后要复用配置，再看 B（手动逐步）。

### 路线 A：快速开始向导（推荐，约 15 分钟）

进入 **托管智能体 → 快速开始**（`/managed/quickstart`）。向导会按下面的步骤逐步引导你：
**选择引擎 → 选择模型接入 → 创建智能体 →（可选）配置环境 →（可选）配置 MCP 凭据库 → 启动会话。**

1. **描述你想要什么**
   在“你想构建什么？”输入框里用自然语言写清需求，例如：
   > “你是一名授权范围内的 Web 安全侦察助手，帮我梳理目标站点的公开信息并给出初步风险清单。”
   或者点 **浏览模板**，直接挑一个现成场景（研究分析、数据处理、运维响应等），系统会帮你预填角色和建议配置。

2. **第一步：选择运行引擎**
   选 **`claude`**（新手最稳）。选完才会进入下一步。

3. **第二步：选择模型接入**
   - 如果你**已经建过**模型接入（见路线 B 第 1 步），从列表里选一个兼容当前引擎的即可。
   - 如果**还没建**，向导允许你**当场创建一个模型接入**：填模型供应商（如 Anthropic）、访问密钥和模型名，测试连接，保存。

4. **创建此智能体**
   引擎和模型接入都就绪后，点 **创建此智能体**。向导接着可能引导你（可选）**配置环境**和 **MCP 凭据库**——第一次可以先跳过，用默认环境。

5. **试运行**
   点 **试运行 / 启动会话**，向导会直接开一个会话。在右侧对话框发一条消息，你就能在左侧看到**实时事件流**——恭喜，你的第一个智能体跑起来了。

> 想深入引擎 / 协议 / 模型接入的完整规则，见 [教程 01](./01-model-provider-setup.md)。

---

### 路线 B：手动逐步（完全掌控，便于复用）

#### 第 1 步：创建一个模型接入（模型与凭据）

进入 **智能体资源 → 模型与凭据**（`/managed/secrets`），点 **新建连接或凭据**：

1. 类型选 **模型接入**（Model Connection）——不是“服务凭据”。
2. （可选）选“计划用于哪个引擎”——它只用来帮你**筛选兼容项**，不会把这条模型接入锁死到某个引擎。
3. 选择**模型供应商**（如 Anthropic、OpenAI、DeepSeek）。
4. 若供应商与引擎只有一个匹配协议，系统自动选好；有多个时你显式选一个。
5. 按提示**填写凭据字段**（如 `ANTHROPIC_API_KEY` + `ANTHROPIC_MODEL`）。
6. 点**测试连接**，通过后**创建**。可勾选“设为该协议的默认模型接入”。

> 一条模型接入的“供应商 + 协议”创建后不可改；要换就新建一条，再到智能体里改引用。
> 常见组合：Anthropic（配 `claude` 引擎）、OpenAI（配 `codex` 引擎）。详见 [教程 01](./01-model-provider-setup.md)。

#### 第 2 步（可选）：准备技能

如果你要让智能体具备特定执行能力（如移动端渗透），进入 **智能体资源 → 技能**（`/managed/skills`）：

1. **导入 ZIP**：拖入一个技能包（包含 `SKILL.md` + 脚本）。
2. 平台会自动**安全扫描**（skillspector）。
3. 把技能推进到 **`approved`（已审批）** 状态，它才允许被智能体使用。

> 只有“已审批 + 扫描通过 + 内容未被改动”的技能，才会在运行时被打进沙箱。完整生命周期见 [教程 03](./03-skills-usage.md)。

#### 第 3 步（可选）：接入外部工具（MCP）

如果要让智能体调用外部 **MCP 工具服务**（如内网扫描器），见 [教程 02](./02-mcp-service-setup.md)：

1. 在**智能体编辑器**的 MCP 区域加一条 MCP 服务器（`type: url` + 名称 + `url`）。
2. 如果该 MCP 服务器需要鉴权，进入 **托管智能体 → MCP 凭据库**（`/managed/vaults`），新建一个 MCP 凭据库，在其中**添加 MCP Bearer 凭据**（填对应的 MCP 服务器 URL + Bearer Token）。
3. 创建会话时**引用这个 MCP 凭据库**。运行时平台会按 URL 自动把凭据注入请求头——你不用把明文 token 写进智能体配置。

#### 第 4 步（可选）：让智能体能访问外网 / 第三方服务（环境 + 服务凭据）

沙箱**默认全禁外网出口**。如果你的智能体或技能需要访问互联网上的主机或某个需鉴权的第三方 HTTP 服务，就要用到**环境**：

进入 **托管智能体 → 环境**（`/managed/environments`），**新建环境**：

1. **网络配置**：选“**限制访问**（推荐）”——默认禁外网，只放行你列出的主机和第三方服务；调试时才用“不限制”。
2. **允许的主机**：填沙箱可直连的外网主机（如 `github.com`、`*.internal.example.com`）。
3. **第三方服务（出站鉴权，可选）**：如果技能要访问一个**需要 token/cookie 的第三方接口**：
   - 先在**模型与凭据**里建一条**服务凭据**（类型选“服务凭据”），把 token 或完整 cookie 存成一个凭据字段（如 `API_TOKEN` 或 `COOKIE_HEADER`）。
   - 回到环境里“添加服务”，填第三方接口的**真实 https 地址**，选择刚才的**服务凭据**、**认证方式**和**凭据字段**。
   - 技能里改用 **http** 访问同一地址；平台会在网关用服务凭据完成认证再回源到 https——**真实 token/cookie 不进沙箱**。

创建会话时，在高级选项里选择这个**运行环境**即可生效。

> 敏感值（token / cookie / API key）**一律存服务凭据**，不要塞进环境的“环境变量”（那里只放非敏感值）。

#### 第 5 步：创建智能体

进入 **托管智能体 → 智能体**（`/managed/agents`），点**新建**，填写：

| 配置项 | 怎么填 |
|---|---|
| **引擎** | 新手选 `claude` |
| **模型接入** | 选第 1 步建好的那条（页面只显示兼容当前引擎的模型接入） |
| **系统提示词** | 写清它的角色和边界，例如“你是一名授权范围内的安全侦察助手” |
| **技能**（可选） | 勾选已审批的技能 |
| **工具 + 策略**（可选） | 勾选内置工具；**对高危工具设 `always_ask`**，运行时会先弹窗让你人工确认 |
| **MCP 服务器**（可选） | 加第 3 步准备的 MCP 服务器 |

保存。智能体会**自动版本化**（每次改动都留快照，可回溯）。

> 完整字段和运行链路见 [教程 04](./04-agent-build-and-run.md)。

## 6. 运行会话并实时观察

无论走 A 还是 B，最终都会得到一个可用的智能体。运行它：

1. 打开该智能体，点 **新建会话**。在高级选项里可以按需选择：**运行环境、MCP 凭据库、文件资源、Memory、Git 仓库**。平台会为这个会话**准备一个专属沙箱**。
2. 在会话里**发送第一条消息**（你的指令 / 目标）。
3. 智能体开始执行，你会在会话里看到**实时事件流**：

| 你会看到 | 含义 |
|---|---|
| 思考过程 | 模型在盘算下一步 |
| 助手文本 | 它给你的回复 |
| 工具调用 / 工具结果 | 它调用了某个工具（内置 / MCP / 自定义）及返回 |
| 模型请求起止 | 每次调模型的 token 计量 |
| 运行 / 空闲状态 | 会话当前是在跑还是等你 |

> 断线重连不会丢事件——平台会从你上次看到的位置续播。

### 需要你参与时（人工确认）

如果某个工具被设成了 **`always_ask`**（尤其是高危操作），智能体执行到这里会**暂停并弹出确认框**：
- 你点**同意**，它继续；
- 你点**拒绝 / 取消**，这一步被叫停。

这是“人在环中（human-in-the-loop）”的安全闸门，建议对危险工具都开启。

### 追加、停止

- 会话运行中你可以**继续发消息**补充指令。
- 想立即停下，点会话里的**停止**；沙箱空闲后由平台自动回收。

## 7. 拿到结果 / 下载报告

智能体完成任务后，产出（如报告文件、扫描结果）通常会：

- 直接以**文本 / 附件**形式出现在会话里，可在会话页面查看或下载；
- 或作为文件产物，在 **智能体资源 → 文件**（`/managed/files`）中找到并下载。

对于“出报告”类场景（如 APK 检测、渗透测试），等会话状态变为**空闲 / 完成**后，
在会话页面即可下载它生成的最终报告。

## 8. 进阶：让智能体自动运行（触发器）

如果你希望智能体**不用手动开会话就能定时或被外部事件触发**，用 **自动化 → 触发器**（`/managed/triggers`）：

- **计划（Cron / 单次）**：按 cron 周期，或在某个设定时间触发一次。
- **Webhook**：外部系统向触发器的端点发一个 HTTP 请求即可启动会话。为安全起见，请开启签名校验——
  **认证方式**可选 HMAC 签名（推荐）、Bearer 令牌或 Token 头，其密钥存成一条**服务凭据**，在触发器里选中它的**凭据字段**。
- **手动**：只通过“立即运行”执行。

创建触发器时选好**智能体**、**触发后执行内容**（提示词，可用 payload 变量）、运行环境、超时/重试/并发策略即可。
连续失败的触发器会被**自动禁用**，可在其详情页重新启用。

## 9. 常见问题（FAQ）

**Q：“模型接入”“服务凭据”“MCP 凭据”有什么区别？我该建哪个？**
A：看用途——
- 要让智能体**调用大模型**：在“模型与凭据”里建**模型接入**。
- 要让技能**访问需鉴权的第三方 HTTP 服务**（或给 Webhook 触发器做入站鉴权）：建**服务凭据**。
- 要让智能体**调用某个 MCP 服务器**：在“MCP 凭据库”里加 **MCP 凭据**。
三者互不替代。

**Q：我该选哪个引擎？**
A：新手一律选 `claude`。等你熟悉了，再按需要试 `codex` / `native` / `pi`。

**Q：为什么我的模型在智能体里选不到？**
A：智能体只显示**与当前引擎兼容**的模型接入。换了引擎后，原来的模型接入可能不兼容——按提示“重新选择模型接入”，或换回原引擎。

**Q：智能体连不上外网 / 访问不了我的目标或第三方服务？**
A：沙箱**默认全禁出口**。要放行，得在**环境**里：把网络设为“限制访问”，在**允许的主机**里加目标域名；如果是需鉴权的第三方服务，再在**第三方服务**里配好**服务凭据**。然后在**创建会话时选中这个运行环境**。

**Q：我的 API token / cookie 会被智能体（沙箱）看到吗？**
A：不会。第三方服务的认证由平台**在网关注入**，技能只用 `http://` 访问同一地址，**真实 token / cookie 不进沙箱**、不写日志、不进事件流。所以敏感值请存**服务凭据**，别放到环境的“环境变量”里。

**Q：技能导入报“Invalid File Type”？**
A：技能包里混进了 `.DS_Store` 或二进制文件。只保留纯文本（`.py` / `.md` / `.json` / `.yaml` 等）再打包。

**Q：技能配好了但智能体没用它？**
A：多半是没过运行时闸门——确认技能是 **已审批**、扫描通过、且导入后**没再改动过内容**；或者你用的是旧会话（沙箱里是开会话那一刻的快照），**重开一个新会话**再试。

**Q：Webhook 触发器怎么保证安全，不被人乱触发？**
A：给它开**签名校验**（推荐 HMAC），把签名密钥存成**服务凭据**并在触发器里选中对应**凭据字段**；还可以设**去重头**和**投递过滤**，只让符合条件的请求真正启动运行。

**Q：项目访问令牌（Project Access Token）是干嘛的？**
A：那是给**外部程序反过来调用 JoySafeter API** 用的（方向和上面的凭据相反）。普通网页使用用不到；需要时在**管理 → 项目访问令牌**里创建，**令牌只显示一次，请立即复制**。

## 10. 术语速查

| 词 | 一句话解释 |
|---|---|
| 引擎 Engine | 跑智能体的运行时（claude / codex / native / pi） |
| 模型接入 Model Connection | “用哪个模型 + 哪把访问密钥”的配置，在“模型与凭据”里建 |
| 服务凭据 Service Credential | 第三方服务出站鉴权 / Webhook 入站鉴权用的 token / cookie，在“模型与凭据”里建 |
| MCP 凭据库 MCP Credential Vault | 存放 MCP 服务器访问凭据（MCP 凭据）的加密仓库 |
| 项目访问令牌 Project Access Token | 供外部程序调用本项目 API 的令牌 |
| 智能体 Agent | 引擎 + 模型接入 + 系统提示 + 技能/工具/MCP 的完整定义 |
| 会话 Session | 你和某个智能体的一段对话，含实时事件流 |
| 任务 Task | 你在会话里发的每条消息，会变成一次被调度执行的任务 |
| 环境 Environment | 智能体运行环境模板：网络策略、允许主机、第三方服务、数据卷、环境变量 |
| 技能 Skill | 可被智能体执行的能力包（脚本 + 说明），需扫描 + 审批 |
| 沙箱 Sandbox | 每个会话独享的隔离容器，默认断网、非 root |
| 触发器 Trigger | 让智能体按计划 / Webhook / 手动自动运行 |
