# Session 自动命名设计

## 目标

从智能体列表、智能体详情或 Quickstart 快捷启动会话时，不要求用户先填写名称，但创建后的会话必须具有稳定、可识别的标题，并在列表、智能体详情和会话详情中一致展示。

## 命名规则

- 用户在完整“新建会话”表单中填写标题时，保留用户标题。
- 请求未提供标题或标题仅包含空白时，由后端统一生成标题。
- 默认格式为：`{Agent Name} · {MM-DD HH:mm}`。
- 时间按平台部署时区 `JOYSAFETER_TIMEZONE` 生成，并兼容回退到 `TZ`；数据库时间戳仍保持 UTC。前端只负责展示，不在不同入口重复生成。
- 自动标题写入 `joysafeter_sessions.title`，不是仅用于界面的临时文本。

## 创建链路

- 智能体列表“启动会话”：继续一键启动，只提交 Agent 引用。
- 智能体详情“启动会话”：继续一键启动，只提交 Agent 引用。
- Quickstart 测试运行：继续直接创建测试会话。
- 会话创建 API 在解析 Agent 后、写入 Session 前补全缺失标题，因此所有入口共享同一规则。
- 完整“新建会话”弹窗继续支持可选的自定义标题。

## 展示规则

- 会话列表名称列显示 `session.title`；仅为兼容旧数据，在标题为空时显示“未命名会话”。
- 智能体详情的会话列表使用相同规则。
- 会话详情页标题优先显示 `session.title`，面包屑保持一致。
- Session ID 在详情页标题下方以 `MonoId` 展示，继续承担排障与复制用途，不再充当主标题。

## 兼容性

- 不回填历史空标题，避免一次无关的数据迁移。
- 历史空标题通过前端“未命名会话”降级展示，不再显示 `-`。
- API 请求和响应字段保持兼容；`title` 仍为可选输入，但创建后的响应应始终包含非空标题。

## 错误与边界

- 用户标题在校验前去除首尾空白。
- 空白标题等同未提供标题。
- Agent 名称为空或异常时，回退为本地化无关的稳定格式 `Session · {MM-DD HH:mm}`。
- 自动生成逻辑必须位于后端，并统一使用平台时区，避免不同入口或重试产生不同名称。

## 测试范围

- 后端：无标题、空白标题、自定义标题和异常 Agent 名称。
- 前端：列表与智能体详情对旧空标题显示“未命名会话”。
- 前端：会话详情优先显示标题，并单独显示 Session ID。
- 回归：智能体列表、详情和 Quickstart 的快捷启动仍保持一键操作。
